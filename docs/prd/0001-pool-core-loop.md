# PRD 0001 — 池塘 Pool：事件中心的校园社交 AI（核心闭环 + 网站形态）

> 状态：ready-for-agent
> 关联：[`DESIGN.md`](../../DESIGN.md)
> 版本：v1.0 · 2026-08-12

---

## Problem Statement

**从学生的视角：**

我在一个两三万人的校园里，不缺可以认识的人，缺的是把身边的陌生同学变成同伴的方法。

具体卡在四个地方：

1. **我说不清我是谁。** 任何产品让我填资料，我都只能填「音乐、电影、运动」—— 这对所有人都一样，等于没填。我真正是谁，藏在我干过的事里，但没有产品会问我干过什么。
2. **我不知道对方会不会理我。** 我看到一个人看起来很合适，但发过去石沉大海的成本太高了，试两次我就不试了。
3. **我不知道第一句说什么。** 就算对方大概率合适，"你好"之后是长久的尴尬，没有第三个东西替我们起头。
4. **就算认识了，也停在那次。** 我加过几十个功能群 —— 抢课群、组队群、拼车群 —— 事情办完，群就死了，关系没有任何后续。我和群里的人，事后依然是陌生人。

**最远的距离不是宿舍到早八教室，是我们都对一件事感兴趣、都想组队，但没有一个人先问一句「要不要一起」。**

现有产品解决不了，是因为它们的底层数据结构错了：`User(profile) + Friendship(edge)`。profile 冷启动填不满，friendship 是个不携带任何信息的布尔值。AI 挂在这样的底层上，只能做「替我说话」，而替我说话会制造虚假繁荣 —— 真正的关系确认环节被跳过了。

---

## Solution

**从学生的视角：**

一个网站。我不填任何资料就能开始用。

我说一句人话：「周六想去爬山，最好野线，能拍照的加分」。

系统给我 3–5 张**候选卡**。每张卡上不只是一个人，还有：我们为什么可能合得来（基于他干过的事，不是他填的标签）、他大概率会回我（系统知道他的回应习惯）、以及一个**具体的行动提案**——「周六 6:00 北宫门集合」，和一句提醒——「他周六下午有课，需早回」。

这些是我的 AI 和他的 AI 先「工作组会晤」出来的。但**AI 到此为止**：连接谁、怎么说、要不要回、记什么，全是我点的。AI 一句话都不会替我发出去。

我点「我来说」，一个**池塘**就开了。池塘里是普通群聊，我们自己聊。AI 在里面默认沉默 —— 只有卡壳的时候它才出面，而且不是插嘴，是**发卡**：时间定不下来就发投票卡，缺人就发清单卡（「带路×1 缺 · 摄影×1 林 · 后勤×1 缺」）。

爬完回来，我传 12 张返图。系统把这次爬山沉淀成这个池塘的记忆，生成一张我们的共同海报，并留下一句 —— **「说好下次去大觉寺」**。

池塘不会因为事情结束就消失，它进入休眠，带着那句话。到时候它会自己醒过来问我们。

而**我的画像，是从这些池塘里自己长出来的**。我从没填过资料，但三次活动之后，系统比任何表单都更懂我 —— 因为它知道我干过什么，以及我在里面扮演什么角色。

同一个池塘结构，在只有两个人时，就恰好是抖音小火人；在长期重复时，会自己长成一个社群 —— 而我从没做过「建群」这个动作。

## User Stories

### A. 冷启动与身份

1. As a 新注册的大学生, I want 不填任何资料就能开始使用, so that 我不会在注册第三步就流失。
2. As a 新注册的大学生, I want 只用一句人话表达我想干什么, so that 我不需要理解产品的分类体系。
3. As a 新注册的大学生, I want 在零历史时也能看到「意图广场」里别人正在发的意图, so that 冷启动期我可以人肉浏览，而不是面对一个空推荐位。
4. As a 用过三次的学生, I want 看到系统从我的活动里蒸馏出的「切面」（运动 / 竞赛 / 手艺…）, so that 我第一次看清自己在别人眼里是什么样。
5. As a 学生, I want 逐个切面设置对外可见度（公开 / 校内 / 熟人 / 私密）, so that 我的运动切面可以给陌生人看，情感切面只给熟人看。
6. As a 学生, I want 编辑或删除任何一条系统蒸馏出的画像描述, so that 系统对我的理解不会失控。
7. As a 学生, I want 知道每条画像是从哪个池塘推出来的, so that 我能判断它是不是冤枉我了。
8. As a 学生, I want 我发过但没成行的意图不进入我的长期画像, so that 一时兴起不会定义我是谁。

### B. 发意图与匹配

9. As a 学生, I want 用自然语言发布意图并看到系统抽出的结构化槽位（时间 / 地点 / 人数 / 强度）, so that 我能当场纠正它理解错的部分。
10. As a 学生, I want 区分「硬条件」和「软偏好」, so that 时间冲突的人不会被推给我，而风格差异可以商量。
11. As a 学生, I want 我的意图有明确的有效期, so that 过期的想法不会一直在广场上挂着。
12. As a 学生, I want 收到 3–5 张候选卡而不是一个长列表, so that 我不需要做筛选工作。
13. As a 学生, I want 每张候选卡都说清「为什么是他」, so that 我能判断这个推荐是不是敷衍。
14. As a 学生, I want 系统优先推给我**会回应**的人, so that 我不会连续三次石沉大海就放弃这个产品。
15. As a 学生, I want 匹配考虑角色互补而不只是兴趣相似, so that 我的爬山队里不会有五个都想带路的人。
16. As a 学生, I want 系统在同校区内匹配, so that 见面成本是可接受的。
17. As a 学生, I want 「换一批」候选, so that 一次不满意不等于走进死胡同。
18. As a 学生, I want 拉黑某人后再也不被推给他/他被推给我, so that 我有退出的权利。
19. As a 热门用户, I want 每天被推荐的次数有上限, so that 我不会被消息淹没到卸载。

### C. 预演与接管（红线）

20. As a 学生, I want 我的 AI 只带我授权可披露的切面去和对方 AI 交流, so that 我的私密信息不会在我不知情时被交换出去。
21. As a 学生, I want 看到预演产出的 3 条共同话题, so that 我知道第一句可以聊什么。
22. As a 学生, I want 看到一个具体的行动提案（时间 + 地点 + 人数）而不是泛泛的「你们可以聊聊」, so that 认识能直接推向做事。
23. As a 学生, I want 看到风险提示（「他周六下午有课」）, so that 我不会提一个注定被拒的方案。
24. As a 学生, I want AI 生成的第一句话我可以直接用、可以改、也可以完全自己写, so that 表述方式的决定权在我。
25. As a 学生, I want **AI 永远不会替我发出任何消息**, so that 每一次连接都是我真的想要的。
26. As a 学生, I want 只有我点了「我来说」连接才成立, so that 我不会莫名其妙出现在一个我没同意的对话里。
27. As a 被匹配方, I want 收到的是一个真人发来的、带上下文的开场, so that 它不像一条群发骚扰。
28. As a 被匹配方, I want 不回应不产生任何社交压力和惩罚, so that 拒绝是安全的。
29. As a 学生, I want 查看我的 AI 在预演里到底说了什么, so that 这个过程对我是可审计的。

### D. 池塘内协作

30. As a 池塘成员, I want 一个正常的群聊, so that 我们能像平时一样说话。
31. As a 池塘成员, I want AI 默认沉默, so that 它不抢占我们之间的互动空间。
32. As a 池塘成员, I want 冷场且关键信息未定时 AI 出面推进, so that 一件想做的事不会因为没人牵头就烂掉。
33. As a 池塘成员, I want 时间/地点分歧时收到投票卡而不是一段 AI 的建议长文, so that 决策一键就能收敛。
34. As a 池塘成员, I want 看到角色清单卡（带路 / 摄影 / 后勤，谁认领了、还缺什么）, so that 我知道我能补哪个位置。
35. As a 池塘成员, I want 我点卡片的动作被直接记进事件流, so that 不需要有人事后再复述一遍。
36. As a 新加入的成员, I want AI 给我一段这个池塘此前发生了什么的摘要, so that 我不用爬三百条聊天记录。
37. As a 池塘成员, I want 全局调低或调高 AI 的介入阈值, so that 话痨与失语之间我说了算。
38. As a 池塘成员, I want 随时 @ 唤起 AI, so that 沉默不等于不可用。

### E. 回流与关系资产

39. As a 池塘成员, I want 活动结束后被提醒传返图, so that 这次经历不会只留在记忆里。
40. As a 池塘成员, I want 系统用我们的返图生成一张共同海报 / 纪要, so that 我们有一件共同作品可以拿出去。
41. As a 池塘成员, I want 看到这个池塘的完整时间线（组队 → 改期 → 成行 → 返图）, so that 这段共同经历是可回看的。
42. As a 池塘成员, I want 系统留下一句「下一次互动的理由」, so that 关系有下一步而不是停在这里。
43. As a 池塘成员, I want 池塘在事情结束后不销毁而是休眠, so that 关系资产不会被清空。
44. As a 池塘成员, I want 休眠一段时间后被那句话唤醒（「上次说好去大觉寺，下周六？」）, so that 我不需要靠自己想起来。
45. As a 学生, I want 看到我和某个人的「关系温度」以及它由什么构成, so that 熟不熟是有依据的，不是我的错觉。
46. As a 反复一起活动的一群人, I want 系统在第三次之后主动提议成立固定社群, so that 社群是长出来的，我从没做过「建群」这个动作。

### F. 精灵（小火人泛化）

47. As a 池塘成员, I want 每个池塘有一只属于这个池塘的精灵, so that 它不属于我们中的任何一个人，只属于这段关系。
48. As a 池塘成员, I want 精灵的外观随我们的活动演化（爬完山皮肤上多一座山）, so that 它是共同投入的证明而不是一个贴纸。
49. As a 池塘成员, I want 双人池塘的精灵在形态上就是小火人, so that 这是小火人的超集而不是另一个东西。
50. As a 池塘成员, I want 精灵能回答「我们上次干了什么」, so that 共同记忆是可以被问出来的。

### G. 网站形态

51. As a 学生, I want 在手机浏览器上完整可用, so that 校园场景下我不需要装 App。
52. As a 学生, I want 落地页在我注册前就讲清楚这个产品和「AI 替你聊天」的区别, so that 我知道我在用什么。
53. As a 学生, I want 深色/浅色跟随系统, so that 晚上刷不刺眼。
54. As a 学生, I want 主要动作（发意图 / 看候选 / 进池塘）在三次点击内到达, so that 它用起来像社交产品而不是后台系统。

### H. 运营与验证

55. As a 产品负责人, I want 一套 1000 虚拟学生 × 12 周事件流的模拟, so that 在没有真实用户时也能证明产品潜力。
56. As a 产品负责人, I want 模拟走的是和真实用户完全相同的代码路径, so that 模拟数据不是假数据。
57. As a 产品负责人, I want 一条「第几次活动之后匹配质量出现拐点」的曲线, so that 冷启动问题有量化答案。
58. As a 产品负责人, I want 看到接管率 / 成行率 / 回流率 / 复现率, so that 我衡量的是真实连接而不是 AI 对话轮次。
59. As a 产品负责人, I want 看到 Agent 发言占比这个反指标, so that 话痨在数据上会被惩罚。

## Implementation Decisions

### ID-1 · 领域模型：Pool 是一等公民

`Person — Pool — Person` 二部超图取代 `User + Friendship`。四种 Pool 共用一张表、一套状态机：

- `intent` 意图池（未成行）· `activity` 具体事件 · `crew` 长期社群 · `dyad` 双人关系池（= 小火人载体）

状态机：`open → matching → forming → active → done → dormant`。**`dormant` 不是终态** —— 池塘持有 `next_hook`，到期可被唤醒并派生新池塘（`parent_pool` 指回本池）。同一 `parent_pool` 链上连续 3 次成行 → 系统提议孵化 `crew`。

「人是什么」不是一张表，是一个沿 `membership → pool → episode/artifact` 的查询。

### ID-2 · 记忆三层，L1 是真相源

| 层 | 内容 | 存储 | 写入成本 |
|---|---|---|---|
| L0 | Intent（带 `expires_at`，过期即死） | Postgres + pgvector | 一次槽位抽取 |
| L1 | Pool / Membership / Episode / Artifact | Postgres | **零 LLM** |
| L2 | Facet / Relation / 知识图谱 | pgvector + Graphiti | 仅在收敛点 |

**硬约束：L1 是唯一真相源，L2 必须可整体删除并从 L1 重建。** L2 不可用时产品降级但不中断（匹配变笨，链路照跑）。

**L2 写入只发生在四个收敛点**：池塘成行、事件回流、周期蒸馏、关系温度重算。一个池塘全生命周期写入 KG 的 episode 数是 3–5，不是几百 —— 这是对 Graphiti 每 episode 多次 LLM 调用、约 50 episodes/分钟吞吐的架构级规避。

**只有落到池塘的意图（`pool_id IS NOT NULL`）才有资格进入 L1 并被蒸馏。** 没成行的想法不构成你是谁。

### ID-3 · 切面按 domain 分片，数量有界

Facet 主键 `(person_id, domain)`，domain 取自固定的 8–12 个生活领域枚举。检索时按意图 domain 取对应切面，不把整个人塞进 prompt。`visibility` 逐切面可控（`public` / `campus` / `warm` / `private`）。Facet 是 Pool 的下游派生物，schema 可随时改而不丢数据。

### ID-4 · 匹配四段漏斗

```
硬过滤(SQL)  →  向量召回(pgvector HNSW, top-200)  →  精排(加权 + cross-encoder, top-20)  →  LLM 终排 + 生成理由(top-3~5)
```

精排打分含两个非共识项，二者都是差异化来源：

- `complementarity(roles_a, roles_b)` —— 从 `membership.role` 历史学角色互补性。纯 embedding 相似度做不到。
- `responsiveness(b)` —— 回应先验。**不推「最合适」的人，推「最合适且会回应」的人。**

外加 `saturation(b)` 惩罚项与每日推荐次数硬上限，防止热门用户被榨干。

权重按用户成熟度三段调度（T0 零池塘 / T1 1–3 个 / T2 ≥4 个）。T0 阶段 `w_social = 0` 是刻意的：没数据就不装有数据，该阶段主打意图广场的人肉浏览。权重后续由各信号在该阶段的 AUC 校准。

### ID-5 · 预演是封闭式的，不是开放对话

`RehearsalMessage` 交换 ≤6 轮，必须产出固定 schema：

```ts
ProposalCard = {
  sharedTopics: [string, string, string],   // 恰好 3 条
  actionProposal: { when, where, size },    // 恰好 1 个，必须具体
  riskNote: string,                         // 恰好 1 条
  openingDraft: string,                     // 草稿，非发送
}
```

用结构化输出（`generateObject` + zod）把 schema 钉死，而非在开放式多轮里往回加约束。

**Agent 输入是「可披露视图」，由数据库 RLS 依据 `facet.visibility` + 关系温度裁剪后产出 —— 不是在 prompt 里叮嘱它别说。** prompt 里的约束是建议，数据库里的约束才是保证。

**不引入 A2A 协议**（它解决跨组织 agent 互操作，我们是同进程两个自家 agent），但 `RehearsalMessage` 字段刻意对齐 A2A `Message`/`Part` 结构，将来开放时加 adapter 即可。**不引入 AG2 / CAMEL**：Python 重框架会造成语言分裂，且 AG2 的 selector 解决「选谁说」，而我们 90% 时间要输出 `SILENT`，语义是反的 —— 抄接口形状，不装依赖。

### ID-6 · Agent 介入策略：默认沉默，输出卡片而非文本

`InterventionPolicy` 接受池塘状态 + 近期转录，返回 `SILENT` 或一张卡。五个触发器：`stall` / `undecided` / `newcomer` / `no_recap` / `hook_due`，其余一律 `SILENT`。阈值用户可调，`@` 可强制唤起。

四种卡：决策卡 / 清单卡 / 回流卡 / 唤醒卡。**卡片优于聊天** —— 点击行为直接写回 `episode`，不需要二次 LLM 解析，既省钱又准确，且不抢占用户互动空间。

### ID-7 · 四条不可协商的人类决策权

| 决策 | 归属 |
|---|---|
| 连接对象 | AI 出候选，真人点 |
| 表述方式 | AI 出草稿，真人可改可弃可自己写 |
| 是否回应 | **AI 永不代答**（`ai_sent_message` 计数必须恒为 0） |
| 记忆内容 | 用户可见、可编辑、可删除 |

这四条是断言，不是目标 —— 违反即为缺陷。

### ID-8 · 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 应用底座 | Supabase（Auth / Postgres / Realtime / Storage / pgvector / **RLS**） | RLS 是隐私边界的落点 |
| 前端 | Next.js 15 + Tailwind，fork `supabase-community/vercel-ai-chatbot` | 聊天 UI + 流式 + 鉴权已连好 |
| Agent 编排 | Vercel AI SDK v5（TS） | 与前端同语言；`generateObject` + zod 做槽位抽取与卡片生成 |
| 记忆 L2 图 | Graphiti（Apache-2.0），官方 `/server` FastAPI | `group_id` = 池塘天然隔离；Leiden `communities` = 社群自动发现；bi-temporal = 关系随时间变化 |
| 向量 | pgvector HNSW | ≤500 万向量与专用库同档，且能与业务表 JOIN |
| 重排 | `BAAI/bge-reranker-v2-m3` | &lt;6 亿参数，消费级 GPU 可跑 |
| 模型 | 火山方舟 `doubao-seed-1-8` | OpenAI SDK 完全兼容，换 `baseURL` 即可 |
| 生图 | `doubao-seedream-4-0-250828` | 多图融合 + 主体一致性 → 精灵皮肤演化与返图海报 |
| IM | 起步 Supabase Realtime | 规模化再换 OpenIM |

**不自建：认证、IM、向量索引、记忆抽取。** 自建仅三层：Pool 语义、匹配编排、Agent 介入策略 —— 它们就是产品本身。

### ID-9 · 模块边界与唯一的注入端口

| 模块 | 职责 |
|---|---|
| `PoolEngine` | **唯一测试缝**。所有状态转移的门面 |
| `Matcher` | 四段漏斗与权重调度 |
| `Rehearsal` | 预演与提案卡生成 |
| `InterventionPolicy` | 断点检测与选卡 |
| `Distiller` | facet / temperature / next_hook（定时 + 触发） |
| `ModelGateway` | **唯一外部端口**。所有 LLM / embedding / 生图调用 |

HTTP handler 与 React server action 是 `PoolEngine` 之上的薄适配器，不含业务逻辑。

### ID-10 · 网站形态

移动端优先的响应式网站，非 App。落地页需在注册前讲清与「AI 替你聊天」类产品的分野（对标 Tara 的产品形态，但理念相反：我们只做预演，不做代答）。深浅色跟随系统。主要动作三次点击内可达。

## Testing Decisions

### 什么算好测试

只测外部可观察行为 —— 给定语料状态与一次输入，`PoolEngine` 产生了什么状态转移、返回了什么。**不测**：prompt 措辞、内部函数调用次数、漏斗中间产物的具体形状。漏斗的四段是实现细节，可以被整段替换而测试不动。

LLM 有随机性，所以**断言写在结构与不变量上**，不写在文案上：候选卡恰好 3–5 张、`ProposalCard.sharedTopics.length === 3`、被拉黑者不出现在结果里、`ai_sent_message === 0`。

### 唯一的缝：`PoolEngine`

测试驱动 `PoolEngine` 的方法，跑在**真实 Postgres**（Supabase 本地 / testcontainers）上，只把 `ModelGateway` 换成确定性替身。

为什么不是 HTTP 边界：会逼每个测试穿过序列化与鉴权，且让模拟器走 20 万次网络。
为什么不是按模块拆纯函数：匹配、蒸馏、策略都依赖真实语料状态，mock 掉 repo 等于在测 mock。

**`seed/simulate.ts` 驱动同一条缝** —— 1000 人 × 12 周就是本项目最大的那个集成测试，不是另一条旁路的 fixture。这直接兑现「同一套代码跑模拟和真实」。

### 覆盖清单

| 目标 | 断言什么 |
|---|---|
| 意图槽位抽取 | 结构完整、hard/soft 分类正确、`expires_at` 被设置 |
| 匹配漏斗 | 硬过滤零漏网（拉黑 / 跨校区 / 时间冲突）；候选数落在 3–5；`saturation` 上限生效 |
| 权重三段调度 | T0 时 `w_social` 对结果零影响（构造反例语料验证） |
| 预演 | schema 形状；**可披露视图不含 `private` 切面**（安全断言，必测） |
| 介入策略 | 五个触发器各自的正例；**大量负例断言 `SILENT`**（这是主路径，不是边缘情况） |
| 状态机 | 非法转移被拒；`dormant` 可唤醒并正确挂 `parent_pool` |
| 蒸馏 | L2 全删后从 L1 重建，facet 与 relation 收敛到等价结果（**L1 真相源的核心回归**） |
| 红线 | `ai_sent_message` 恒为 0；四条决策权对应的 API 不存在绕过路径 |

### 现有参照

仓库为 greenfield，无既有测试可参照。测试栈随主链路统一为 TS（Vitest）。Graphiti 的 Python 服务通过 `ModelGateway` 同侧的端口注入，本仓库不直接测它 —— 它是可降级依赖。

## Out of Scope

- **原生 App**（iOS / Android）。本期只做移动端优先的网站。
- **A2A 协议的实际实现**。仅在 `RehearsalMessage` schema 上对齐字段，不起 Agent Card / task 状态机。
- **精灵世界**（多池塘精灵进入公共空间互动）。结构上支持（`pool × pool` 相遇），本期不做。
- **Qdrant / OpenIM 替换**。pgvector 与 Supabase Realtime 在本期容量内够用，替换属规模化阶段。
- **bge-reranker 自托管**。起步用 LLM 终排，重排模型待精排质量成为瓶颈时再上。
- **跨校区匹配**。`campus_id` 是硬隔离的第一道墙，本期单校区。
- **支付、报名费、AA 分账**。
- **内容审核与举报的完整体系**。本期只做拉黑与基础频控。
- **可视化玩法层**（把池塘渲染成植物 / 播种等隐喻）。后端结构已覆盖，前端表现层留到 Phase 3 之后。
- **让运营可视化配 Agent prompt / workflow**（Coze Studio 旁挂）。等有运营角色再说。

## Further Notes

**与赛题四问的对应**（评审判据，不是装饰）：

| 赛题问题 | 落点 |
|---|---|
| 服务哪一段关系 | 同一结构贯通全段，关系阶段是 `temperature` 的连续函数 |
| AI 介入哪个环节 | 四个断点，ID-4 / ID-5 / ID-6 各自负责一段，其余时刻沉默 |
| 哪些决策留给真人 | ID-7 的四条断言 |
| 沉淀什么关系资产 | Pool 本身：共同角色、共同作品、共同记忆、`next_hook` |

**北极星指标**：接管率 → 成行率 → 回流率 → **复现率**（由 `next_hook` 唤醒并再次成行的比例）。复现率是最重要的一个，它量化「关系之所以持续不是因为永远有话说，而是一直有事可做」。

**反指标**：Agent 发言占比（越低越好）、AI 代答次数（恒为 0）。指标定成这样，刷量没有收益。

**已知风险**：Graphiti 写入成本已在 ID-2 架构级规避；冷启动质量差在 ID-4 中被诚实处理而非掩盖；Agent 话痨在 ID-6 与测试覆盖中被双重约束。

**遗留待定**：本 PRD 假定测试缝为 `PoolEngine`（进程内门面）+ `ModelGateway`（唯一外部端口）。若该判断被推翻，Testing Decisions 整节需重写，Implementation Decisions ID-9 随之调整；其余各节不受影响。
